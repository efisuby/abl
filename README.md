# ABL — Audio Book Listener

Android-плеер аудиокниг с библиотекой на Яндекс.Диске: книги хранятся в облаке,
скачиваются на устройство для офлайн-прослушивания, прогресс и закладки
синхронизируются между устройствами.

Версия 1.0.0 готова к публикации в Google Play и RuStore (изменение 006): материалы магазинов и список действий владельца — в `docs/store/`. Приложение не содержит рекламы и аналитики, своего сервера нет.

## Что умеет

Экраны (отдельные Activity, русский и английский интерфейс, светлая и тёмная темы):

- **Библиотека** — поиск, фильтры (статус, «на устройстве»/«в облаке»), сортировка, группировка по сериям, карточка «Продолжить слушать», проценты прослушанного, мини-плеер внизу (играющая книга, пауза/воспроизведение, тап открывает плеер), кнопка «Добавить» (папка, файл, Яндекс.Диск), «Облако» и «Настройки» на панели.
- **Книга** — шапка (серия, прогресс, статус), закладки, главы; меню «Изменить» (название, автор, чтец, серия, обложка) и «Удалить».
- **Плеер** — стрелка «назад» и переход к экрану книги, крупная кнопка воспроизведения, главы, скорость 0,5–3,0, перемотка ±15 с, таймер сна (в том числе «до конца главы»), закладки, управление с экрана блокировки и из уведомления.
- **Оформление** — русский и английский, тема светлая / тёмная / как в системе (Настройки).
- **Импорт** — папка или один файл с устройства или из Google Drive (через системный выбор файлов), mp3-папки и m4b с главами, метаданные из тегов, обложка.
- **Яндекс.Диск** — вход через Яндекс ID, ленивый обзор папок, добавление книги и скачивание с докачкой, проверкой md5, повторами каждые 15 с (до 15 попыток) и режимом «только Wi-Fi».
- **Выгрузка в облако** — локальную книгу можно отправить в `Приложения/AudioBookPlayer/books/<название>` через меню книги: по файлу, с проверкой md5, режимом «только Wi-Fi» и продолжением с места обрыва. Прогресс и закладки сохраняются, книга появляется на других устройствах.
- **О приложении** — версия, политика конфиденциальности, лицензии открытых компонентов, обратная связь (Настройки → «О приложении»).
- **Настройки** — язык, тема, «только Wi-Fi», занятое место и «Удалить все загрузки», кнопка «Синхронизировать» и время последней синхронизации, аккаунт.

Сценарии:

1. Войти через Яндекс ID → выбрать книгу на Диске → скачать → слушать офлайн, в том числе с заблокированным экраном.
2. Импортировать книгу с устройства → слушать, ставить закладки.
3. Синхронизация между устройствами: позиция, закладки, скорость, метаданные и обложки. Запускается при старте, при выходе из плеера, при появлении сети и кнопкой. Без сети изменения уходят при следующем запуске, с повтором по нарастающей паузе.
4. Переустановка: после входа список книг возвращается из `library.json` как «в облаке» (аудио скачивается по запросу), вместе с позициями и закладками.

Файлы синхронизации лежат в `Приложения/AudioBookPlayer`: `progress/<deviceId>.json`, `settings/<deviceId>.json`, `bookmarks.json`, `library.json`, `covers/<bookId>.jpg`. Подробности и причины решений — в `openspec/changes/001-android-audiobook-player/design.md`.

## Ограничения

- Токен Яндекса живёт около года, обновления нет: раз в год нужно войти заново.
- Книги, импортированные с устройства, остаются только на нём, пока их не выгрузить в облако (меню книги); до этого после переустановки они не восстанавливаются.
- Книга, удалённая на одном устройстве, остаётся в `library.json` и вернётся на новом устройстве. Восстановление выполняется один раз на установку.
- Если один из файлов книги на Диске отдаёт HTTP 500, загрузка останавливается на нём после второго одинакового ответа, а экран книги называет файл и код ошибки. Можно повторить или пропустить файл — остальные скачаются.
- Синхронизация не использует условную запись (API Диска её не даёт): конфликты разрешаются при чтении — последняя запись побеждает по `updatedAt`, закладки объединяются.
- Вход через Яндекс ID нужен только для облака; импорт с устройства или Google Drive, воспроизведение и закладки работают без аккаунта.

## Требования

- JDK 21
- Android SDK: `platforms;android-36`, `build-tools;36.0.0`
- Путь к SDK в `android/local.properties` (файл не коммитится):
  ```properties
  sdk.dir=/path/to/Android/Sdk
  ```

## Сборка

```bash
cd android
./gradlew :app:assembleDebug     # debug APK
./gradlew :app:assembleRelease   # release APK (R8 + shrinkResources), для RuStore
./gradlew :app:bundleRelease     # release AAB, для Google Play
./gradlew :app:lintDebug
```

APK: `android/app/build/outputs/apk/{debug,release}/`, AAB: `android/app/build/outputs/bundle/release/app-release.aab`.
Google Play подписывает приложение своим ключом, а загруженный AAB — ключом загрузки (`abl-release.jks`); у каждого ключа свой SHA-256, и все они должны быть в консоли Яндекс OAuth (см. `docs/store/owner-actions.md`).

## Тесты

Все юнит- и инструментальные тесты одной командой (нужен запущенный эмулятор `abl-api36`; при подключённом телефоне выберите устройство через `ANDROID_SERIAL`):

```bash
cd android
ANDROID_SERIAL=emulator-5554 ./gradlew :app:testDebugUnitTest :app:connectedDebugAndroidTest
```

Результат на 2026-10-26: юнит-тесты и 66 инструментальных (эмуляторы API 36 и API 24, AVD `abl-api24`), 0 падений; `lintDebug` — без замечаний, `openspec validate --strict` проходит.
`connectedDebugAndroidTest` удаляет приложение с устройства после прогона.

## Подпись

Debug и release подписываются одним ключом, чтобы отпечаток сертификата
(SHA-256), указанный в OAuth-приложении Яндекса, не менялся между сборками.

Создайте `android/keystore.properties` по образцу `keystore.properties.example`:

```properties
storeFile=/absolute/path/to/abl-release.jks
storePassword=...
keyAlias=abl
keyPassword=...
```

Без этого файла сборка проходит, но release-APK остаётся неподписанным, а debug
использует стандартный отладочный ключ.

Ключ и пароль нужно хранить в надёжном месте: их потеря ломает и обновления
поверх установленной версии, и вход через Яндекс ID.

## Яндекс.Диск

OAuth-приложение типа «Для авторизации пользователей» с платформой
«Android-приложение». В консоли указываются:

- package name: `com.efisuby.abl`
- SHA-256 отпечаток ключа подписи
- права: `cloud_api:disk.read`, `cloud_api:disk.write`, `cloud_api:disk.info`

`client id` не является секретом и задаётся в `android/app/build.gradle.kts`
(`yandexClientId`). `client secret` приложению не нужен.
